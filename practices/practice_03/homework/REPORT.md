# Домашняя работа 3: локальный помощник по своему проекту — отчёт (A/B)

Короткий итог:
- Локальная модель Ollama подключена к OpenCode; чтение файлов подтверждено событиями tool_use (read) в логах JSONL.
- Проведено A/B‑сравнение с изменением единственного фактора — system prompt (A: краткий; B: строгий). Остальные условия фиксированы.
- По поведению и формату выбрана конфигурация B (строгий prompt): устойчивее к домыслам, требует file:line, корректно обрабатывает «нет данных» и ложные предпосылки.

## 1) Окружение и воспроизводимость

- ОС/железо: WSL2 (Ubuntu) поверх Windows; CPU: AMD Ryzen 3 5425U (8 vCPU по WSL); GPU: нет; RAM WSL ~3.5 GiB; Swap ~1.0 GiB; свободный диск ~935 GiB.
- Инструменты:
  - Ollama 0.34.4 (локальный сервер), OLLAMA_NO_CLOUD=1
  - OpenCode v2.0.27 (CLI)
  - Python 3.13.14 (в WSL), GNU Make 4.4.1, curl 8.18.0
- Локальный API подтверждён:
  - curl --fail http://localhost:11434/api/tags — список моделей содержит itmo-agent:latest
  - curl --fail http://localhost:11434/v1/models — endpoint OpenAI‑совместимого API доступен
- Замечание об окружении: OpenCode и Ollama запускались в WSL, чтобы избежать NAT‑несоответствия localhost Windows↔WSL. Это устранило «ConnectionRefused» часть времени; оставшиеся редкие сбои сглажены повторами и меньшими лимитами.

## 2) Модель и конфигурации

- Базовая модель: ollama/itmo-agent (FROM qwen3.5:2b)
  - Параметры (ollama show): architecture qwen35; parameters ~1.9B; quantization Q8_0
  - Контекст max (по модели): до 262144; рабочий num_ctx ~32768; размещение: CPU
- Провайдер для тестируемого помощника: локальный Ollama endpoint http://localhost:11434/v1
- Агент тестируемого помощника: local-guide (только чтение)
  - Разрешения: { "*": deny, "read": allow } (в demo также glob/grep при необходимости)
  - steps: 5 (уменьшено для стабильности)
  - Лимиты модели (per‑dir opencode.json): context 32768, output 1024
- System prompts:
  - A (repo-system-A.txt): «Ты — локальный помощник… Отвечай строго на основе прочитанных файлов… Приводи file:line. Работай только с файлами текущего каталога и подпапок»
  - B (repo-system-B.txt): строгая версия с запретом выдумывать, обязательными file:line, отказом при ложной предпосылке и тем же ограничением по путям
- Файлы конфигурации:
  - practices/practice_03/lab/demo/opencode.json (вариант A)
  - practices/practice_03/homework/demo_b/opencode.json (вариант B)
  - Доп. конфиги: practices/practice_03/homework/CONFIG_A.json, CONFIG_B.json

Подтверждённые вызовы read (примеры):

Такие случаи отмечены как «запуск не завершился», без подстановки придуманного ответа. Для подтверждения факта чтения использованы повторные прогоны r1–r3 (там есть tool_use read по нужным путям).

## 7) Анализ A vs B

- Точность: B чаще избегает домыслов, корректно сообщает об отсутствии данных (q5), подчёркивает ложные предпосылки (q6). Для q2/q4 точность упиралась в выбор входных файлов (не в формулировку prompt).
- Формат: B стабильно требует file:line и короткий ответ — это удобно для проверки.
- Скорость и стабильность: B сопоставим с A; на q6 медиана заметно лучше (51.35s vs 101.91s). Снижение лимитов и шагов улучшило устойчивость обеих конфигураций.
- Ошибка/граница: периодические ConnectionRefused к локальному endpoint приводили к отсутствию финального ответа в основных файлах. Мы не подменяли результаты — зафиксировали как незавершённый запуск и подтвердили чтение по r‑прогонам. Также были попытки чтения по неверным путям до введения ограничения «только текущий каталог».

Выбор: оставляем конфигурацию B (строгий system prompt) — меньше домыслов, требование file:line, корректная реакция на ложные предпосылки и отсутствие данных, формат удобен для проверки.

## 8) Как воспроизвести

В WSL, с поднятым Ollama:
```bash
export OLLAMA_NO_CLOUD=1
ollama serve # в отдельном окне

# Серии повторов (warm + r1..r3):
cd ~/ITMOv2/practices/practice_03/homework/scripts
bash ab_run.sh
python3 metrics.py
python3 compare.py > ../results/compare.json

# Основные A/B прогоны (с повторами при пустом файле):
bash run_primary.sh
python3 metrics.py
python3 compare.py > ../results/compare.json
```

Файлы отчёта и артефактов:
- Отчёт: practices/practice_03/homework/REPORT.md (этот файл)
- Результаты: practices/practice_03/homework/results/
  - qN.{A,B}.jsonl — 10 основных файлов
  - qN.{warm|r1|r2|r3}.{A,B}.jsonl — повторы
  - metrics.json — медианы времени
  - compare.json — наличие финальных ответов и вызовов read
  - gold.json — эталоны ответов

## 9) Приложение: system prompts

- A (repo-system-A.txt):
  «Ты — локальный помощник по проекту. Отвечай строго на основе прочитанных файлов. Если данных нет — скажи, что в репозитории нет ответа. Приводи точные ссылки file:line. Работай только с файлами текущего каталога и его подпапок; используй относительные пути при чтении.»

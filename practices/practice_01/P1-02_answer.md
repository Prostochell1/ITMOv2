# P1-02: Повторное ревью с master prompt

Источник: @practices/practice_01/TRAINING_PR.diff

summary:
- PR добавляет POST `/api/reviews`, который принимает JSON с ключом `diff` и возвращает `{ "comment": <ответ LLM> }`. Логика `ReviewService.review` формирует промпт и синхронно вызывает `LLM.generate` без валидации входа, лимитов размера, таймаута и маскирования секретов.

risks:
1. Отсутствует валидация входа в API (правило QA-1, формат контракта OUT-1 под угрозой)
   - file: app/api.py
   - line: 36–38
   - evidence: используется `payload["diff"]` без проверки наличия/типа; при отсутствии ключа будет `KeyError` и 500
   - risk: непредсказуемые 5xx вместо контролируемого 4xx на невалидном запросе

2. Нет таймаута и обработки ошибок LLM (REL-1)
   - file: app/review_service.py
   - line: 19–22
   - evidence: прямой вызов `self.llm.generate(prompt)` без try/except и без ограничений по времени
   - risk: подвисания/5xx при ошибках провайдера или больших diff

3. Отсутствует редактирование секретов в prompt и лимит размера diff (SEC-1, API-1)
   - file: app/review_service.py / app/api.py
   - line: 19–22 (формирование промпта), 36–38 (приём входа)
   - evidence: diff подставляется целиком в строку промпта, отсутствуют проверки длины и очистка секретов
   - risk: утечка чувствительных данных во внешний LLM; перегрузка/ошибка при diff > 20 000 символов

checks:
- Позитивный: POST `/api/reviews` c телом `{ "diff": "diff --git a/app/x.py b/app/x.py\n..." }` → 200 и JSON с ключом `comment`.
- Негативный: POST `/api/reviews` без поля `diff` → 422/400 (сейчас наблюдается 500 из-за `KeyError`).
- Граничный: тело с `diff` длиной 20 001 символ → 413 (API-1); до доработок ожидается 200/5xx.
- Надёжность: эмулировать исключение из `LLM.generate` → контролируемый 502/504 в ответе и отсутствие 5xx без тела.

Примечания:
- Вывод подтверждён строками diff и правилами из CASE.md (SEC-1, API-1, REL-1, OUT-1, QA-1). Анализ выполнен по TRAINING_PR.diff без обращения к внешним источникам.
